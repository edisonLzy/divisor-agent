Harness engineering: the hidden layer of capable agents

Anthropic Engineering · Jun 12, 2026

When people evaluate an agent, they often focus on the model. But the model is only one part of a system that has to observe, decide, act, and learn from the environment around it.

We use the term harness engineering to describe the work of designing the environment in which an agent operates. It includes the tools an agent can call, the feedback it receives, the context it carries forward, and the checks that keep it on task.

The environment is part of the capability

A strong harness makes useful work easier to discover and mistakes easier to recover from. The goal is not to prescribe every action, but to make the next good action legible.

A model can be capable in isolation yet ineffective when its environment hides the state it needs to make decisions. This distinction becomes acute when an agent works across many tools, files, and long-running tasks.

Good feedback loops turn uncertain attempts into visible progress. They narrow the gap between an action and its consequence, giving both the agent and its operator a shared view of what changed.

Designing for recovery

Reliable systems expect interruption. They retain enough context to resume, give people clear places to intervene, and leave an inspectable trail of decisions.

The best agent interfaces treat human feedback as a resource for learning, not merely a request for correction.

That changes the role of the interface: it becomes a place to build understanding together, rather than a thin layer over a model call.
